# go-tinker

Unofficial Go client for the Thinking Machines Tinker API, generated with oapi-codegen. If you only want to use the client from an agent, read [.agents/skills/go-tinker/SKILL.md](.agents/skills/go-tinker/SKILL.md) instead; this file is about changing the repo.

## Architecture

The client is generated end to end. `gen.go` holds the `//go:generate` steps that `make generate` runs:

Spec fetch (`scripts/fetch-spec.sh`) → patch (`scripts/fix-nullable-types.sh`) → oapi-codegen with `config.yaml` → `client.gen.go`.

- `scripts/fetch-spec.sh` reads `openapi_spec_url` from the `.stats.yml` of thinking-machines-lab/tinker, then downloads that Stainless URL to `api/openapi.yaml`. The URL carries a content hash and changes on every spec update.
- `scripts/fix-nullable-types.sh` rewrites OpenAPI 3.1 type lists (`type: [number, 'null']`) into `type` plus `nullable: true`, drops the duplicate `nullable` key the spec has next to them, and writes `api/openapi.fixed.yaml`.
- `config.yaml` maps `number` (and `format: float`) to `float64` and sets the response wrapper suffix to `HTTPResponse`.

## Stack

- Go 1.26.9, one package `tinker` at the module root.
- `github.com/oapi-codegen/runtime` at runtime; oapi-codegen and golangci-lint as `go tool` dependencies.
- No logging: it is a library.

## Layout

- `gen.go`: package doc and the generate steps.
- `config.yaml`: oapi-codegen config.
- `client.gen.go`: generated, committed.
- `client_test.go`, `example_test.go`: tests and the README example.
- `scripts/`: spec fetch, spec patch, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make generate  # download the spec and regenerate client.gen.go
make dep       # go mod tidy + go mod vendor
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Without `response-type-suffix: HTTPResponse`, oapi-codegen's collision resolver names OptimStep's response wrapper `OptimStepResponse2`, which is already the name of a union member alias of the `OptimStepResponse` schema, and the output does not compile.
- The spec's `servers` entry is a host it labels internal. The README and the skill use the default base URL of the official Python SDK instead.
- CI skips the generate drift check, because `make generate` always pulls the newest upstream spec. Regenerate locally and commit the result.
- `RetrieveFuture`'s 200 body is a raw JSON union. An `As...` decode for the wrong kind can succeed with empty fields.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
